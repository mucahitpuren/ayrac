> Visual and interaction contract for Phase 1: Private Shelf (Walking Skeleton). Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note (mvp mode):** this phase covers AUTH-01, AUTH-02, AUTH-05, AUTH-07, LIB-01,

## Cross-Cutting Rules

These apply to every screen in this phase, not just one.

- **`<html lang>` follows the active i18n locale** (`tr` / `en`) and updates live when the user
  switches language. Required because CSS `text-transform: uppercase` only folds Turkish
  `ı/İ` correctly under `lang="tr"` (kind labels, badges use uppercase).
- **Breakpoint:** use Tailwind's default `sm:` (640px, close to the sketches' 600px container
  query) as the single mobile/desktop split for Phase 1. Plain media-query responsive variants
  are enough here — the sketches' `@container` query is not required until a component needs to
  respond to something other than the viewport.
- **No real covers exist yet** (COVR-* ships in Phase 4). Every cover slot — library tiles,
  siblings cards, the copy-detail hero — renders the same static placeholder: a centered
  Phosphor `Book` glyph on a solid `--color-surface-2` tile, `--radius-cover` (2px) corners,
  `--shadow-cover`. This is a **different, solid style from the striped "missing series volume"
  ghost tile** in the locked layout findings (`.cover.ghost`) — that striped pattern is reserved
  for Phase 6 series gaps and must not be reused for "no cover uploaded" or the two will read as
  the same thing to users later.
- **Copy-detail hero tint** always falls back to `--color-primary` (per the locked CSS pattern's
  documented fallback), since there is no uploaded cover to extract a tint from in Phase 1.
- **Font weights loaded:** Fraunces 600 only; DM Sans 400 and 600 only. This is a documented
  subset of the full family the sketches reserved (DM Sans 400/500/600/700) — later phases may
  load 500/700 as needed, Phase 1 does not use them.
- **Session bootstrap:** on app load, before Supabase resolves whether a session exists, show a
  centered "Yükleniyor…" / "Loading…" state (spinner) instead of a flash of the login page or an
  empty shell.

## Spacing Scale

Base 4px scale. Every declared spacing value in this contract is a multiple of 4 — including the
two values below that the sketch source CSS expressed off-scale (34px/30px hero padding,
22px/14px phone grid gap). The sketches are throwaway HTML mockups for visual direction, not the
production token system (`sketch-findings-ayrac` SKILL.md), so Phase 1 snaps those two to the
nearest 4px-scale value rather than carrying an arbitrary pixel value into the Tailwind
implementation. Each snap preserves the proportion the sketch validated (hero padding stays
top-heavier than bottom; the phone grid gap stays tighter than the 28px/20px desktop gap) — no
locked visual decision changes, only the exact pixel value.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, badge/pill padding |
| sm | 8px | Compact stacks, input internal vertical padding |
| md | 16px | Default form field gaps, card padding on phone, **phone library-grid column gap** (snapped from the sketch's 14px) |
| — | 20px | Top-bar horizontal padding on phone, **phone library-grid row gap** (snapped from the sketch's 22px), **desktop library-grid column gap** (unchanged — already on-scale) |
| lg | 24px | Card padding on desktop, section stacking |
| — | 28px | Copy-detail hero bottom padding (snapped from the sketch's 30px), library-grid row gap on desktop |
| xl | 32px | Page horizontal padding on desktop, top-bar horizontal padding on desktop, copy-detail hero top padding (snapped from the sketch's 34px) |
| 2xl | 48px | Space above major page sections |
| 3xl | 64px | Reserved — not used by any Phase 1 screen |

Notes:
- `--radius-lg` 14px (cards) and `--radius-md` 8px (controls) are shape tokens, not spacing —
  see `## Color` for the full shape table. Border-radius is exempt from the 4px spacing scale by
  definition; this is not a spacing exception.
- Library grid gap: **28px row / 20px column** on desktop stays as originally specified (both
  already on-scale); **20px row / 16px column** on phone (snapped from the sketch's 22px/14px).
  `minmax(0, 1fr)` columns still apply (`layout-navigation.md` — required to stop a long title
  like "Gençler İçin Fotoğraflarla Nutuk" from stretching a column).
- Copy-detail hero padding: **32px top / 28px bottom** (snapped from the sketch's 34px/30px,
  `copies-detail.md`).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f4efe6` light / `#1d1914` dark (`--color-bg`) | Page background |
| Secondary (30%) | `#fbf8f2` / `#26211b` (`--color-surface`), `#ece5d8` / `#312a22` (`--color-surface-2`) | `--color-surface`: cards, top bar, form panels. `--color-surface-2`: cover-placeholder tiles, subtle fills, input backgrounds |
| Accent (10%) | `#8a4b2a` light / `#e0a57f` dark (`--color-primary`) | See reserved-for list below |
| Destructive | `#b3392a` light / `#e08a72` dark (`--color-danger`, soft: `#f3ddd4` / `#3a2620`) | Delete actions only — see below |

Accent (`--color-primary`) reserved for: primary submit buttons (Kayıt ol, Giriş yap, Kitabı
kaydet, Nüshayı kaydet, Değişiklikleri kaydet, Kitap ekle, Yeni nüsha ekle), the focused-input
border/ring, cross-links between auth screens
(e.g. "Kayıt ol" link on the login card), and the avatar's initial-letter background. **Not**
used for body text, default borders, or neutral icons.

**Destructive color is new in this UI-SPEC** — the sketch-findings theme (`default.css`) defines
`--color-success` / `--color-success-soft` but no danger token, since no sketch screen needed one.
`#b3392a` / `#e08a72` is a warm, desaturated brick-red picked to sit in the same family as the
existing terracotta/success tokens rather than importing a cold alarm-red. Structure mirrors the
success token exactly: a soft background variant for inline badges/banners, a solid variant for
the destructive `Button`/`AlertDialog` action. Reserved for: the "Nüshayı sil" / "Delete copy"
action row button, the destructive `AlertDialog` confirm button ("Evet, sil"), and inline
delete-failure toast/error text. Solid destructive buttons use white text in light mode and `--color-bg`
(`#1d1914`) text in dark mode — the same pattern the locked primary-button rule uses ("`color:
var(--color-bg)` on `--color-primary`, works in both modes").

Shape tokens (locked, unchanged): `--radius-md: 8px` (controls), `--radius-lg: 14px` (cards),
`--radius-cover: 2px` (covers/placeholders). `--shadow-cover` per theme file.

### Delete confirmations (LIB-09)

`{format} · {publisher}` below (and everywhere else it appears — hero meta line, sibling cards)
drops the ` · {publisher}` part when publisher is empty, leaving just `{format}`.

**Delete a copy, other copies of the work remain:**
- Title — TR "Bu nüshayı sil?" · EN "Delete this copy?"
- Body — TR "{format} · {publisher} nüshasını silmek üzeresin. Bu eserin {n} nüshası daha
  kalacak. Bu işlem geri alınamaz." · EN "You're about to delete the {format} · {publisher}
  copy. {n} more cop{y|ies} of this work will remain. This can't be undone."
- Buttons: Vazgeç / Evet, sil · Cancel / Yes, delete

**Delete a copy that is the work's last copy (work is deleted too):**
- Title — same as above.
- Body — TR "{format} · {publisher} nüshasını silmek üzeresin. Bu, eserin son nüshası; eser de
  silinecek. Bu işlem geri alınamaz." · EN "You're about to delete the {format} · {publisher}
  copy. This is the work's last copy, so the work will be deleted too. This can't be undone."
- Buttons: same as above.

**Delete a whole work (explicit "Eseri ve nüshalarını sil" action):**
- Title — TR "Bu eseri sil?" · EN "Delete this work?"
- Body — TR "\"{title}\" eserini ve {n} nüshasını silmek üzeresin. Bu işlem geri alınamaz." ·
  EN "You're about to delete \"{title}\" and its {n} cop{y|ies}. This can't be undone."
- Buttons: same as above.
- After confirming, redirect to `/` (library).
