<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test runner (service key) → dev Supabase | Admin privileges bypass RLS |
| browser bundle → Supabase | Only the publishable/anon key may cross |
| developer shell → Supabase CLI | Access token + DB passwords |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-02-01 | Elevation of Privilege | service/secret key reaching the client bundle | high | mitigate | Key only in `.env.test.local` read via `TEST_` prefix; referenced only from `tests/setup/`; `assertClientSafeKey` refuses secret keys at client creation; acceptance greps `src` for SERVICE_ROLE |
| T-01-02-02 | Tampering | automated tests hitting prod data | high | mitigate | `getTestEnv()` guard requires SUPABASE_PROD_PROJECT_REF and refuses URLs containing it (D-12, prohibition P2) |
| T-01-02-03 | Denial of Service | orphaned throwaway accounts on dev | low | mitigate | `ayrac-test+` prefix, afterAll `sweepTestUsers()` |
| T-01-02-04 | Information Disclosure | DB password passed as CLI argument | low | accept | Local single-user machine; value comes from a gitignored file and is never echoed |
| T-01-02-05 | Spoofing | weak passwords on sign-up | medium | mitigate | Server-side minimum length 8 on both projects, proven live by auth-config test |
</threat_model>
